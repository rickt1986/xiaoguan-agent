销冠智能体 · 系统建设方案

K12教育私域顾问团队 · 知识蒸馏 + AI陪练 + 实时建议

项目定位

将top顾问的隐性经验（对话技巧、异议处理、促单节奏）转化为可复用的结构化知识资产，通过AI陪练帮助新人快速上手，通过实时建议系统辅助顾问在实战中提升转化率。

核心价值：从"口口相传"到"系统复制"，让销冠能力的复制不再依赖师傅带徒弟，而是可量化、可迭代、可规模化的系统工程。

1 系统架构详解

整个系统采用四层架构设计，自下而上依次为：数据采集层 → 知识蒸馏层 → 知识库层 → 应用层。

1.1 数据采集层

数据源 采集方式 数据类型 关键挑战
电话录音 呼叫中心API / 企微通话录音 音频文件（mp3/wav） ASR准确率、方言识别
企微/微信聊天 企微会话API / SCRM导出 文本记录（结构化/非结构化） 隐私脱敏、上下文断裂
CRM系统 CRM API对接 用户画像、成交记录、跟进轨迹 多系统数据打通
人工标注 销冠自标注 + 运营审核 最佳话术片段标签 标注一致性与质量
关键设计点： 数据采集层需要建立统一的原始数据湖，所有来源的数据打上「顾问ID + 用户ID + 时间戳 + 成交结果」的四元组标签，为后续蒸馏环节的质量评分提供关联依据。

1.2 知识蒸馏层

这是整个系统的核心引擎，负责把原始对话数据提炼为结构化知识。蒸馏层分为四个子模块：

子模块 功能 技术方案
话术分类 将对话切分为功能段落：开场白 → 需求挖掘 → 方案展示 → 异议处理 → 促单 → 跟进 LLM few-shot分类 + 规则匹配
场景标签 给每段话术打上多维度标签：学段（小学/初中）、家长类型（焦虑型/理性型/价格敏感型）、核心痛点 NER实体抽取 + LLM标签推理
结构化提取 将话术段转为可复用的QA对、话术模板、策略卡片 LLM指令抽取 + 模板填充
质量评分 关联成交结果，对每段话术打分；成交对话的话术获得高权重 成交率排序 + 人工审核

蒸馏提示词设计要点

第④步LLM话术蒸馏是整个管道的智力核心，提示词设计直接决定知识质量：

  • 输入约束：明确传入对话上下文 + 场景标签 + 顾问成交结果
  • 输出格式：强制结构化JSON输出（话术类型、场景标签、原文片段、改写模板、适用条件、禁忌事项）
  • few-shot示例：预先标注3-5个高质量范例作为few-shot，引导LLM产出标准
  • 质量阈值：设定置信度阈值，低于阈值的转入人工审核队列

1.3 知识库层

蒸馏后的知识需要三种存储形式，服务于不同的检索场景：

存储 用途 技术选型 数据特点
向量数据库 语义检索（RAG）—— 当顾问遇到特定场景时，用语义相似度找到最匹配的销冠话术 Milvus / 腾讯云VectorDB / Qdrant 话术embedding + 元数据过滤
结构化知识库 按场景树状组织的话术模板库、QA对库 PostgreSQL + JSON字段 支持精确过滤、版本管理
用户画像库 典型家长画像模型，用于陪练角色模拟和实时建议的上下文 结构化表 + 向量索引 画像维度 + 行为模式

1.4 应用层

AI陪练系统

面向新人 新入职顾问无需等待师傅有空，随时可以启动AI陪练进行模拟实战训练。

  • 场景选择：选择学段（小学/初中）、家长类型（焦虑型/理性型/价格敏感型）、核心痛点（成绩焦虑/升学压力/费用顾虑）
  • 角色扮演：AI基于知识库中的典型家长画像，扮演对应类型的家长，按照真实对话节奏推进
  • 多轮对话：AI会根据顾问的回答动态调整难度——回答得好就加大异议力度，回答不好就给出提示
  • 实时评分：从话术准确度、逻辑连贯性、节奏控制、情感共鸣四个维度实时打分
  • 练习报告：训练结束后生成薄弱点定位报告 + 个性化改进路径 + 推荐学习的话术片段
  • 排行榜：团队内练习积分排行，形成良性竞争氛围

实时建议引擎

面向实战 顾问在实际跟用户沟通时（电话或企微聊天），系统实时分析对话内容，给出话术建议。

  • 实时输入：电话场景——ASR实时转写流推送；聊天场景——企微消息webhook推送
  • 上下文分析：LLM实时分析当前对话阶段（开场/需求挖掘/异议处理/促单）、用户情绪、关键异议点
  • 知识库检索：基于当前场景语义检索top销冠的话术，按成交率排序取最优
  • 策略卡片：以卡片形式在顾问侧屏展示建议话术（可一键复制）、异议处理方案、当前阶段提醒
  • 延迟控制：从用户说完话到建议卡片出现，控制在3-5秒内（ASR流式 + LLM流式输出）
  • 反哺机制：顾问采纳/修改/忽略的反馈数据回流知识库，持续优化推荐质量

2 技术选型建议

模块 推荐方案 备选 选型理由
ASR语音转写 腾讯云ASR（实时+离线） 阿里云/讯飞 企微生态内集成成本低，实时流式ASR延迟低
LLM推理 DeepSeek-V3 / Qwen2.5-72B GLM-4 / 私有化部署 性价比高，中文话术理解能力强，支持私有化
Embedding模型 bge-m3 / text-embedding-v3 本地部署 中文语义检索效果优，支持混合检索
向量数据库 Milvus（自建）/ 腾讯云VectorDB Qdrant / Chroma 支持百万级向量，元数据过滤能力强
后端框架 Python FastAPI + Celery Go + Redis AI生态丰富，异步任务处理蒸馏管道
前端 Vue3 + WebSocket React 企微侧边栏集成方便，WebSocket支持实时建议推送
消息队列 Redis Streams / Kafka RabbitMQ 实时建议场景的低延迟消息推送
部署 腾讯云容器服务TKE 自建K8s 与企微/CRM同云部署，网络延迟低
省钱策略： ASR离线转写用便宜的长录音接口（约0.1元/分钟），实时建议场景才用流式ASR。LLM调用区分档次——蒸馏管道用72B大模型保证质量，实时建议用14B小模型保证延迟。蒸馏是一次性成本，实时建议是持续成本。

3 实施路线图

整体分三期推进，每期都有可独立交付的MVP，避免"建了半年不能用"的局面。

第一期 1-2月

知识库冷启动 + AI陪练MVP

目标：完成数据采集管道搭建，首批蒸馏100-200条top销冠话术入库，陪练系统跑通基础流程

· 对接企微会话API + 呼叫中心录音接口

· 搭建ASR转写 + LLM蒸馏管道（离线批处理）

· 建立向量数据库 + 话术模板库基础结构

· AI陪练MVP：支持3个核心场景（小学焦虑家长/初中升学/价格异议），多轮对话 + 基础评分

· 交付物：陪练Web应用 + 知识库管理后台

第二期 3-4月

实时建议引擎 + 陪练进阶

目标：实时建议引擎上线（先聊天场景，后电话场景），陪练系统扩充场景库和评分维度

· 企微侧边栏应用开发：实时消息分析 + 策略卡片推送

· 流式ASR + 流式LLM推理管道搭建（延迟控制3-5秒）

· 知识库扩充至500+话术模板，覆盖8-10个核心场景

· 陪练进阶：难度分级、弱点针对性训练、团队排行榜

· 交付物：企微侧边栏实时建议插件 + 陪练2.0

第三期 5-6月

闭环优化 + 规模化

目标：建立"实战数据 → 知识库 → 陪练 → 实战"的闭环迭代机制，全量推广

· 顾问采纳率/转化率数据回流分析，优化推荐算法

· 管理后台完善：顾问能力画像、知识库效果看板、ROI分析

· 电话场景实时建议上线（呼叫中心集成）

· 全团队推广 + 培训体系搭建（新员工入职必修陪练课）

· 交付物：管理后台3.0 + 电话实时建议 + 运营SOP

角色 人数 职责 关键能力
项目经理 / PM 1 需求管理、进度把控、跨部门协调 懂业务+懂技术，K12私域经验
后端工程师 2 数据管道、API、企微集成、实时推理服务 Python/FastAPI、消息队列、WebSocket
AI算法工程师 1-2 蒸馏提示词工程、RAG优化、模型调优 LLM应用、Prompt Engineering、RAG
前端工程师 1-2 陪练Web应用、企微侧边栏、管理后台 Vue3、WebSocket、企微JS-SDK
业务专家 / 标注员 1-2 话术审核、场景设计、评分标准制定 资深销冠或销售管理经验
运维 / DevOps 0.5（兼） 容器部署、监控、成本管控 K8s/腾讯云、CI/CD

关键提醒：业务专家是成败关键

技术团队再强，没有懂业务的专家参与标注和审核，蒸馏出来的知识库就是"正确的废话"。建议从现有top顾问中抽调1人，或由销售主管兼任，每周投入至少2天参与话术审核和场景设计。这个角色的投入度直接决定知识库的质量上限。

6 数据合规与安全

必须解决的合规问题

风险点 应对措施
用户隐私数据泄露 所有原始对话在入蒸馏管道前先做PII脱敏（手机号、姓名、身份证号等用NER识别后替换）
录音授权合规 确认呼叫中心录音已有用户授权；企微聊天数据使用需符合企微数据使用规范
未成年人数据保护 K12场景下用户是家长（成年人），但对话中可能涉及未成年人信息，需额外脱敏
数据存储安全 原始录音加密存储、知识库访问权限分级（顾问只能看话术模板，不能看原始对话）
LLM数据安全 蒸馏使用私有化部署模型或可信API，确保对话数据不外泄给第三方

7 关键风险与应对

风险 影响 应对
ASR准确率不足 蒸馏出的话术质量差，"垃圾进垃圾出" 优先选普通话清晰的录音做首批蒸馏；人工审核第一轮输出；逐步积累方言/口音训练数据
知识库"正确但无用" 话术模板看起来都对，但实际用不出来 业务专家深度参与标注，确保每条话术都有适用场景+禁忌事项+原文出处；陪练中验证可用性
实时建议延迟超标 顾问等不及，建议变成"事后诸葛亮" 流式ASR + 小模型推理 + 预计算常见场景话术；设定3秒超时降级为"稍后总结"
顾问抵触心理 觉得被监控，不愿意使用 定位为"赋能工具"而非"监控工具"；先从陪练切入（非实战场景）；数据不直接用于绩效
知识库维护衰减 话术过时，不再适应当前市场 建立月度知识库review机制；自动标注低使用率/低采纳率条目提醒更新

8 待确认问题

以下问题需要老大拍板，直接影响方案细化和排期：

  1. 现有系统对接情况：目前用的是哪个呼叫中心/电话系统？企微还是个人微信做私域？CRM是什么系统？这些系统的API开放程度如何？
  2. 录音数据量：目前每月大概有多少通顾问电话？其中top顾问占比多少？现有录音保存多久了？
  3. 预算范围：整体预算大概在什么量级？是自建团队还是外包？如果预算有限，优先做哪个模块？
  4. 团队技术能力：内部有没有研发团队？技术栈是什么？还是需要完全外包？
  5. 上线时间要求：有没有明确的deadline？比如赶在某个招生旺季前上线？
  6. 合规现状：电话录音的合规授权目前是怎么做的？企微聊天数据的使用有没有合规审批？
  7. 销冠配合度：top顾问愿意配合标注和录音分析吗？需不需要激励机制？

下一步建议

1. 先回答上面的关键问题，我来细化方案和排期

2. 如果现有条件允许，建议先用1-2周做概念验证（POC）：拿10通销冠录音 → ASR转写 → LLM蒸馏 → 看看产出的话术质量是否达标

3. POC通过后，按三期路线图正式启动
